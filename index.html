One registration. Many user connections.

An OAuth app identifies your integration to a provider. Each user then grants it access to their own account, and a provider or a customer admin may need to approve it first.

  1. 1

    You register the app

    Add its name, a callback URL where users return after signing in, and the permissions it needs. You receive a client ID and, for server apps, a secret.

  2. 2

    The provider may review it

    Whether this applies depends on the provider, the data you request, and who will use the app. Marketplace listings and customer admin approval are separate decisions.

  3. 3

    Each user connects

    The user signs in with the provider and approves specific permissions. Your app receives a token for those permissions, never the user's password.

Using a managed OAuth app instead?

Some integration platforms let you borrow an OAuth app they already registered and, in some cases, already got reviewed. That can remove steps 1 and 2. Step 3 never goes away: each user still consents, and customer admins keep their controls. The consent screen normally shows the platform's app name, and you are usually limited to the scopes that app was approved for.

Privacy and use notes

This site never asks for provider passwords, OAuth client secrets, or access tokens. Checklist progress is stored only in your browser. A research request sends the app name and website you enter to this service and its AI model.
